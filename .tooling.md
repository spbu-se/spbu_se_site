# Local Tooling Quirks

<!-- encoding: utf-8 -->

Only local host / environment workarounds. Not project design decisions.

## Git & GitHub CLI

### `git commit` hangs on Windows

If GPG is configured (`user.signingkey`) but KeePass/password storage is locked, `git commit` waits indefinitely for unlock. Use `--no-gpg-sign` for staging/feature commits. Only merge commits to `current` need signoff.

### `git cherry-pick --continue` tries to GPG-sign and fails

With `commit.gpgsign=true`, `git cherry-pick --continue` attempts to sign the new commit and stalls/fails with `gpg: signing failed: Timeout`. Use `git cherry-pick --continue --no-gpg-sign`, or if hooks already applied the staged changes, commit them directly with `git commit --no-gpg-sign -m "<msg>"` and clear the cherry-pick state. `git cherry-pick -n` followed by an explicit `git commit --no-gpg-sign` avoids the stall entirely.

### `git rebase --continue` hangs on GPG sign + editor (no TTY)

With `commit.gpgsign=true`, `git rebase --continue` after a conflict tries to GPG-sign the replayed commit and also opens the editor for the commit message — both hang in a non-interactive shell. Workaround:

```powershell
git config commit.gpgsign false
$env:GIT_EDITOR="true"   # set in the SAME command as the continue
git rebase --continue
git config commit.gpgsign true   # restore after the rebase finishes
```

`GIT_EDITOR` is process-local and does not survive across bash calls — set it in the same invocation as `rebase --continue`. Also pre-set `$env:GIT_EDITOR` for the final pick's commit step.

### `gh pr merge --delete-branch` is blocked when a merge queue is enabled

The repo uses a merge queue, so `gh pr merge --squash --delete-branch` fails with `Cannot use -d or --delete-branch when merge queue enabled`. Merge without the flag, then delete the fork branch manually after the PR shows `MERGED` (prove via `gh pr list --state merged --json headRefName`): `git push origin --delete <branch>` and `git branch -D <branch>`.
