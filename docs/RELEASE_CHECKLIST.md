# Release Checklist

<!-- encoding: utf-8 -->

Pre-release guardrail: the files and structures to verify or update before tagging `vYYYY.MM.DD`. Run it before every release; the release process lives in `docs/DEVELOPMENT_PROCESS.md` §6.

Covers: release-time drift items (dates, counts, hardcoded values), verification steps. Does not cover: release-note generation — see `.skills/release-notes/`, versioning rules — see `docs/GIT_FLOW.md` §Versioning, general quality gates — see `docs/QUALITY_MANAGEMENT.md`.

## A. Must-update (verify each release; stale items are fixed in the release commit)

| # | File | What to update | When |
|---|------|----------------|------|
| A1 | `src/sitemap.py` | `STATIC_LASTMOD` (default) to the release date | Every release — crawlers read this as the static-page lastmod; a stale value silently ages the sitemap |
| A2 | `src/templates/base_{dark,light,*_footer_white}.html` (×4) | Copyright year `1996-YYYY` → `1996-<current year>` | Year changes; all four bases must stay in sync |
| A3 | `src/templates/summer_school.html` | Title/description year must match the `school` dict for the served year | When a new summer-school year is added in `src/flask_se_summer_schools.py` |
| A4 | `docs/TESTING.md` §4a reference-run line | Test count/coverage of the latest full green run | Release cadence — the note documents the current suite size |
| A5 | `docs/SEO_A11Y_ROADMAP.md` §5 | Mark shipped PRs as done | After each SEO/agent PR merges |

## B. Check-only (verify; fix only if broken)

| # | Item | Check |
|---|------|-------|
| B1 | `requirements.txt` vs `uv.lock` | Regenerate if deps changed: `uv export --no-dev --no-hashes > requirements.txt` (`docs/DEVELOPMENT_PROCESS.md` §Definition of Done). CI fails on mismatch |
| B2 | `.github/workflows/` (ci.yml, deploy_to_production.yml) | `actionlint` passes; `deploy_to_production.yml` deploys on `release: published` (not tag push), and its `release` job still reads `.tmp/release-notes.md` with `mkdir -p .tmp` present |
| B3 | `src/static/assets/img/og/` (10 files) + `apple-touch-icon.png` | **D7 guardrail**: if the site design changed since generation, re-run `uv run python .tmp/gen_og_images.py` — stale previews degrade social shares silently (see `docs/DESIGN_DECISIONS.md` [2026-08-13]) |
| B4 | Static site build | `uv run python src/flask_se.py build` succeeds (Frozen-Flask; only if the freezer is used) |
| B5 | `Dockerfile` / `docker-compose.yml` | Update only if Python dependencies changed (`docs/DEVELOPMENT_PROCESS.md` §6) |
| B6 | `docs/API_REFERENCE.md` | New/changed routes since last release are listed (`/llms.txt`, `/humans.txt`, `/robots.txt`, `/sitemap-*.xml`) |
| B7 | `src/flask_se_bachelor.py` | Admission-cycle year + PDF URLs match the current campaign (data, not code) |
| B8 | `robots.txt` + `llms.txt` | `robots.txt` still points at `Sitemap.xml`; `llms.txt` links resolve; private paths still disallowed |
| B9 | `.tmp/` hygiene | No release-note draft or scratch leaked to the repo root (all under `.tmp/`, gitignored) |
| B10 | Release-notes draft | `.tmp/release-notes.md` generated by the skill; Part 1 has no dev jargon (enforced by skill prompt) |
| B11 | Tag discipline | Tag is GPG-signed (`git tag -s vYYYY.MM.DD`), pushed only to `upstream`, at `current`; pushing the tag alone does **not** deploy — prod deploys only after the release is **published** (see `docs/GIT_FLOW.md` §7) |
| B12 | CI on `current` | `gh run list --branch current --limit 1 --json conclusion` green before tagging |
| B13 | Full test suite | `uv run pytest --tb=no -q` green; record result for A4 |
