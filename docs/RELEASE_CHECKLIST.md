# Release Checklist

<!-- encoding: utf-8 -->

Pre-release guardrail: the files and structures to verify or update before tagging `vYYYY.MM.DD`. Run it before every release; the release process lives in `docs/DEVELOPMENT_PROCESS.md` §6.

Covers: release-time drift items (dates, counts, hardcoded values), verification steps. Does not cover: release-note generation — see `.skills/release-notes/`, versioning rules — see `docs/GIT_FLOW.md` §Versioning, general quality gates — see `docs/QUALITY_MANAGEMENT.md`.

## A. Must-update (verify each release; stale items are fixed in the release commit)

> Auto-derived, no manual bump: the sitemap `STATIC_LASTMOD` and the asset
> cache-busting version (`?v=`, via the `asset()` macro → `ASSET_VERSION`) both
> read `SE_SITE_LASTMOD` at deploy (defaults to today) — see B14; the footer
> copyright uses the `{{ current_year }}` template global.

| # | File | What to update | When |
|---|------|----------------|------|
| A1 | `src/templates/summer_school.html` | Title/description year must match the `school` dict for the served year | When a new summer-school year is added in `src/flask_se_summer_schools.py` |
| A2 | Reference-run block in `docs/TESTING.md` §4 (xfail Policy) | Test count/coverage of the latest full green run | When the suite size/counts change (feature-driven), not per release — B13 records it |
| A3 | `docs/SEO_A11Y_ROADMAP.md` §5 | Mark shipped PRs as done | After each SEO/agent PR merges |

## B. Check-only (verify; fix only if broken)

| # | Item | Check |
|---|------|-------|
| B1 | `uv.lock` vs `pyproject.toml` | `uv lock --check` (pre-push + CI enforce parity); commit `uv.lock` if deps changed. The prod install is `uv sync --frozen --no-dev` (`extra/deploy.sh`); CI fails on any drift |
| B2 | `.github/workflows/` (ci.yml, deploy_to_production.yml) | `actionlint` passes; `deploy_to_production.yml` deploys on `release: published` (not tag push); its `verify-signature` job gates deploy on a GPG-verified tag and its `release` job still runs with `mkdir -p .tmp` present |
| B3 | `src/static/assets/img/og/` (10 files) + `apple-touch-icon.png` | **D7 guardrail**: if the site design changed since generation, re-run `uv run python .tmp/gen_og_images.py` — stale previews degrade social shares silently (see `docs/DESIGN_DECISIONS.md` [2026-08-13]) |
| B4 | **Security alerts triage (pre-release gate)** | No untriaged open alerts on the default branch. Dependabot: `gh api "repos/spbu-se/spbu_se_site/dependabot/alerts?state=open" --jq '.[] \| "\(.number) \(.security_advisory.severity) \(.dependency.package.name)"'`; code scanning: `gh api "repos/spbu-se/spbu_se_site/code-scanning/alerts?state=open"`; secret scanning: `gh api "repos/spbu-se/spbu_se_site/secret-scanning/alerts?state=open"`. Triage each (fix, or dismiss with a recorded reason) per `.skills/security-audit/`; stale alerts whose pinned version is already patched auto-resolve — document, do not dismiss |
| B5 | Prod install path | `uv sync --frozen --no-dev` (the `extra/deploy.sh` uv branch) succeeds on Python 3.13 (`.python-version`) |
| B6 | `docs/API_REFERENCE.md` | New/changed routes since last release are listed (`/llms.txt`, `/humans.txt`, `/robots.txt`, `/sitemap-*.xml`) |
| B7 | `src/flask_se_bachelor.py` | Admission-cycle year + PDF URLs match the current campaign (data, not code) |
| B8 | `robots.txt` + `llms.txt` | `robots.txt` still points at `Sitemap.xml`; `llms.txt` links resolve; private paths still disallowed |
| B9 | `.tmp/` hygiene | No release-note draft or scratch leaked to the repo root (all under `.tmp/`, gitignored) |
| B10 | Release-notes draft | `.tmp/release-notes.md` generated by the skill; Part 1 has no dev jargon (enforced by skill prompt) |
| B11 | Tag discipline | Tag is GPG-signed (`git tag -s vYYYY.MM.DD`), pushed only to `upstream`, at `current`; pushing the tag alone does **not** deploy — prod deploys only after the release is **published** (see `docs/GIT_FLOW.md` §7) |
| B12 | CI on `current` | `gh run list --branch current --limit 1 --json conclusion` green before tagging |
| B13 | Full test suite | `uv run pytest --tb=no -q` green; record result for A2 |
| B14 | `SE_SITE_LASTMOD` at deploy | Production must set `SE_SITE_LASTMOD` at deploy from the release tag (`vYYYY.MM.DD` → `YYYY-MM-DD`); it drives both the sitemap static `lastmod` and the asset `?v=` version. Verify `curl -s https://se.math.spbu.ru/sitemap-static.xml` shows the release date as `lastmod`, not today |
| B16 | **Maps key on prod** | The 3 map pages (index, contacts, bachelor_admission) render maps only when a provider key is configured on the deploy host: Yandex preferred (`SE_YANDEX_MAPS_KEY` or `YANDEX_MAPS_KEY=` in `configs/flask_se_maps.conf`), else Google (`SE_GOOGLE_MAPS_KEY` or the legacy single-value file). Post-deploy verify a provider is active (`curl -s .../contacts.html | grep -o 'SE_MAPS_PROVIDER = "[^"]*"'`); when neither key is set the map boxes must show the "Источник карты не задан" placeholder, not a blank 500px box |
| B15 | **Strict signing gate (hard rule)** | Deploy/release only with a **GPG-signed tag**. `verify-signature` job in `deploy_to_production.yml` fails the run when the tag is lightweight or not GPG-verified (checks GitHub's git-data API `verification.verified`); the `deploy` job depends on it. Before creating the draft release, also run `git verify-tag vYYYY.MM.DD` locally — if it fails, STOP. Publishing an unsigned tag is a process violation |
| B17 | **DB auto-migration (self-healing)** | The app runs `ensure_schema()` at boot (gated by `SE_AUTO_MIGRATE`, fault-tolerant for multi-worker gunicorn) — idempotent: fresh DB → `init_db()`/`create_all`; existing DB → backup + `ensure_schema()` PRAGMA-driven `ADD COLUMN` (backup is best-effort: a read-only `databases/` dir must not block repair). A `flask db` CLI group (`upgrade`/`migrate`/`revision`) delegates to `ensure_schema()` so webhook-driven deploys that call `flask db <subcommand>` keep working. No ops pre-flight needed. **Verify after deploy: the app boots and `users.deleted` (or any recent model column) exists** — the 2026-08-25 incident deployed `users.deleted` in the model for 15h without the prod DB getting the column (webhook `flask db` silently failed after Alembic removal). Post-deploy smoke: `curl -s -o /dev/null -w "%{http_code}"` must be 200 for `/`, `/theses.html`, `/news/`, `/login.html`, `/diplomas/` (note: real routes are `/news/` and `/login.html`), and when `/logs` is enabled (`SE_LOGS_ENABLED=1`) it must not show `no such column` OperationalErrors — see `docs/TOOLING.md` §Auto-migrate |
| B18 | **PD compliance (recorded)** | Roskomnadzor operator-register lookup for СПбГУ (ИНН 7801002274) — record the реестровый номер + date in `docs/PRIVACY_COMPLIANCE.md` §4.5. Metrica stays dormant (decision §5 #7) unless the department later enables analytics |
